# Independent review of sql/068–079, and what was done about it

At 23:30 a separate reviewer (fresh context, not anchored on the author's
reasoning) read the night's migrations against the existing app and the
spec's rules, and confirmed each finding by running it against the real
migrations in PGlite. Kevin had already applied the migrations to production
at that point, so every fix is a NEW migration: **083** (what affects
production today) and **084** (partner features, before the first
partnership). Each fixed finding has a test that reproduces the original
attack and now expects it to fail (`sql/test/reviewFixes.test.ts`,
`sql/test/partnerFixes.test.ts`).
